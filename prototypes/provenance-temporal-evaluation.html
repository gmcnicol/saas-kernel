Minimum contract under test

  • Input: subject, Projected State at one version, explicit evaluation time, and exact Semantic Pack version.
  • Output: typed Facts, Applicable Action IDs, and optional earliest reevaluation time.
  • Provenance: state version, evaluation time, pack version, and derivation or applicability policy ID on every result.
  • Correction: append a domain Event, advance Projected State version, and evaluate immediately. Never edit an old Event or Evaluation Snapshot.
  • Reevaluation Worker: an in-process background loop claims durable due work containing subject, expected state version, pack version, and due instant. It discards stale work, catches up after downtime, and queues the current evaluation's successor.
  • Deployment: no separate daemon and no cron job per subject initially. A later topology decision may move the same worker loop into its own process.
  • Excluded: generic evidence nodes, confidence scores, source taxonomies, domain calendars, and presentation explanations.
