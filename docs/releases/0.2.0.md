# SaaS Kernel 0.2.0

The production-proven typed Application/Kernel and prepared scalar authorisation baseline, published as two same-version Maven artifacts:

- `io.github.gmcnicol:saas-kernel:0.2.0`
- `io.github.gmcnicol:saas-kernel-taxi-generator:0.2.0`

Registry: `https://maven.pkg.github.com/gmcnicol/saas-kernel`. GitHub Maven authentication is required even for public packages. See [release and consumption instructions](https://github.com/gmcnicol/saas-kernel/blob/v0.2.0/docs/releasing.md).

## Included

- The reviewed typed Kernel/Application contracts and generator metadata.
- Prepared scalar Cedar reads, the bounded immutable-condition/Action patch, native provenance, and allocation improvements already proven by Kit.
- Matching runtime/generator versions, flattened consumer POMs, sources, Javadocs, detached OpenPGP signatures, SHA-256 receipts, and a tagged source identity.
- Exactly two Maven artifacts. The prepared native implementation remains embedded in the runtime JAR; consumers do not build or install Rust, and there is no third native artifact.

The producer gate covers Java correctness/public contracts, owned Rust tests, isolated generated-binding/package/native adoption, and both example Application images. A separate final consumer uses a new empty Maven repository and the actual registry coordinates; local staging is not substituted for published availability. See the signed `release.json`, `SHA256SUMS`, and independent `kernel-adoption.properties` assets for the final hashes and source commit.

## Known limitations

**Performance exception:** the human explicitly accepted shipping 0.2.0 after the unchanged protected-read gate measured three-client fenced-context p95 **137.519ms**, above the **<100ms** target with three total JDBC connections. Correctness and packaged-consumer checks passed; this release does not claim that latency gate passed. No workload, sample count, fence, or production pool setting was changed. [Kit #121](https://github.com/hi-kit-co-uk/kitt-saas/issues/121) tracks stabilisation. The [baseline report](https://github.com/gmcnicol/saas-kernel/blob/v0.2.0/docs/trusted-main-baseline.md) retains the failed run and separate capacity diagnostic.

**Advisory work remains open:** Cedar Java SDK 4.2.3 is retained. [#76](https://github.com/gmcnicol/saas-kernel/issues/76), [#77](https://github.com/gmcnicol/saas-kernel/issues/77), and [#78](https://github.com/gmcnicol/saas-kernel/issues/78) track SDK/advisory-specific work; this release does not claim those assessments or fixes are complete.

The prepared native route is supported on Linux x86_64 with glibc >=2.36. Other platforms retain the original SDK route without additional platform/performance certification. Resource accounting is bounded admission, not hard native preemption. No universal tail-latency, bit-reproducible archive, 1.0 API stability, or production Application deployment is claimed.

## Version policy

This is a pre-1.0 release. Patches preserve backwards compatibility; minor releases add capabilities or explicitly document a break. Runtime and generator versions move together. Published coordinates and source tags are never overwritten; a partially published version is retired rather than repaired by replacing bytes.
