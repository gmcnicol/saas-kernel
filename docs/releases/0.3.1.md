# SaaS Kernel 0.3.1

Security and lifecycle fixes with no intended public Java API, generated-contract, database-schema, native ABI, or deployment-guard configuration change. This is a backwards-compatible patch: values that could change Cedar kinds and responses with policy errors or warnings now fail closed rather than granting authority.

## Cedar boundaries

- Upgrade Cedar Java from 4.2.3 to 4.11.0 for patched literal serialization and public schema introspection.
- Preserve typed Cedar value kinds across prepared reads, uncached SDK reads, and workflow authorisation. Reject reserved record escapes and schema-guided record/string promotion, including nested capability/context values.
- Require workflow ALLOW responses to contain no warnings or policy errors. An errored forbid cannot silently permit an Action.
- Preserve existing prepared admission, encoding, depth, deadline and native limits. Workflow validation does not introduce an aggregate read-wire byte ceiling.

The prepared scalar Rust/JNI bridge remains embedded. Upstream SDK caching stays disabled because it discards schema warnings required by Kernel's stricter contract. There is no bridge removal or new native target.

## Lifecycle

Close an unreturned prepared evaluator if factory setup fails after native preparation. Preserve the original failure and suppress cleanup failures. Regression tests cover native-handle conservation without GC, close/evaluate seams, failed preparation/encoding recovery, and retained-bundle admission accounting.

## Adoption and limits

Use the exact matching pair and regenerate bindings:

- `io.github.gmcnicol:saas-kernel:0.3.1`
- `io.github.gmcnicol:saas-kernel-taxi-generator:0.3.1`

The existing deployment-guard budget remains **request-pool maximum + one separately owned PostgreSQL connection per Application instance**. No downstream dependency pin or deployment changes automatically.

Linux x86_64/glibc >=2.36 remains the prepared platform. The earlier packaged qualification exercised glibc 2.43/2.36, rejection plus SDK fallback on glibc 2.35, and unsupported unmodified Alpine/musl. ARM64, macOS and Windows execution remain unqualified. Close is not a per-evaluator join or hard native preemption guarantee.

[Advisory assessment](../cedar-advisory-assessment.md), [JNI qualification](../jni-qualification.md), and [platform compatibility](../platform-compatibility.md) retain their original source/artifact identities and failed-run limits. Their private 0.3.0-labelled artifacts and performance samples are historical evidence, not signed 0.3.1 artifacts or a new 0.3.1 performance measurement. This release is not a complete downstream audit or all-platform certification. Remaining evidence gates in #76–#78 stay open.

Published 0.3.0 bytes and receipts remain immutable. Registry availability is established only when the main-merge pipeline completes signing, registry verification and its fresh-consumer proof.
