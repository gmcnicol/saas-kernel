# SaaS Kernel 0.2.1

Fixes request-pool starvation caused by the Semantic Pack deployment guard. The guard now owns one separately accounted, non-pooled PostgreSQL connection instead of permanently borrowing a request connection.

The lifetime shared advisory lock, exclusive checksum update, equivalent-version overlap, incompatible-version exclusion, migration protection, and session-loss shutdown remain unchanged. No authorisation, RLS, disclosure fence, native implementation, schema, or generated contract change is intended.

## Connection budget

Budget **request-pool maximum + one deployment-guard connection per Application instance**, plus any separately configured migration/administrative connections. A pool maximum of three now leaves all three slots available to requests and permits four runtime database sessions in total. A one-slot request pool remains usable after startup.

The revised test envelope was explicitly approved: **three request connections + one guard = four total**, with the same workload, observations, warmups, checks, fences, heap/CPU and latency targets. This is not a claim that the previous three-total-connection gate passed. The failed 137.519ms context measurement remains recorded in [Kit #121](https://github.com/hi-kit-co-uk/kitt-saas/issues/121).

## Configuration and safety

The default uses an independent non-pooled datasource derived from the runtime connection configuration, preserving supported driver and SSL/options properties. It never returns a live lock-bearing session to the request pool. Opaque/custom datasource configurations that cannot be safely derived fail closed with explicit configuration guidance rather than silently dropping security settings. See [operators](../operators.md) for the dedicated-datasource override.

The guard requires a session-preserving PostgreSQL endpoint; a transaction-pooling proxy cannot own a lifetime session lock. Keep the guard on the same database and runtime login as the Application.

Both exact coordinates move together:

- `io.github.gmcnicol:saas-kernel:0.2.1`
- `io.github.gmcnicol:saas-kernel-taxi-generator:0.2.1`

Version 0.2.0 is unchanged and must not be overwritten. Native stays embedded; consumers do not compile Rust. Cedar Java SDK 4.2.3 and the open SDK/advisory investigations remain unchanged; this is not an advisory-fix or all-platform certification claim.
