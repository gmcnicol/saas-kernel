# SaaS Kernel 0.3.2

Completes advisory regression coverage and reconciles the acceptance evidence for #76–#78. The original-kind, strict-diagnostics and lifecycle fixes already shipped in 0.3.1; this release adds tests and documentation, not another evaluator/native implementation change.

## Additional coverage

- Typed template-link principal/resource IDs and template/result policy identifiers retain quotes, backslashes, newlines, Unicode and injection payloads on SDK/prepared routes. Exact/mismatched scope controls preserve permits, matching forbids and policy identity.
- Public PostgreSQL-backed reads and all disclosure operations reject entity/extension-shaped converter or capability maps and schema-valid errored forbids.
- Advisory attacks before preparation, during formatting and after provider response cannot release new provider/sink bytes after the failing fence. Previously authorised delivery is not retroactively recalled.
- Intentional isolated original-kind and final-fence reversions each make all eight disclosure cases fail. Restoring the existing guards passes; these are mutation proofs, not new defects in 0.3.1.

## Qualification and compatibility

[Acceptance and evidence](../cedar-issue-resolution.md) maps each issue's requirements to executable coverage, retained source/artifact receipts and explicit limits. The signed 0.3.1 native binary matches the historically qualified implementation. Earlier private artifacts, performance observations and failed runs retain their original identities; there is no new 0.3.2 performance or all-platform certification claim.

No intended public API, generated contract, database schema, native ABI, evaluator, resource-limit or deployment-guard configuration change. Upstream SDK caching stays disabled; SDK 4.11.0 and the embedded prepared bridge remain unchanged. Runtime/generator metadata moves together:

- `io.github.gmcnicol:saas-kernel:0.3.2`
- `io.github.gmcnicol:saas-kernel-taxi-generator:0.3.2`

Keep the existing request-pool maximum plus one independent deployment-guard connection. No downstream dependency pin or deployment changes automatically. Published 0.3.1 bytes remain immutable. Registry availability requires successful signing, registry verification and the main pipeline's fresh-consumer proof.
