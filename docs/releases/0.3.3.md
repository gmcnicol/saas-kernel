# SaaS Kernel 0.3.3

Build the producer once, test that output, and publish that exact release bundle. No runtime authorisation, public API, database schema, native ABI or resource-limit change is intended.

## One build, immutable promotion

- PR CI runs one `clean install`, including the complete verification lifecycle, native/public-contract suites and isolated packaged consumers.
- CRM/Ledgerling fixture image checks use the already-built executable JARs with `build-image-no-fork` in the same job. Before/after hashes reject any JAR mutation. The separate reactor/image rebuild job is removed; these fixture images are not deployed products.
- A main push runs only version checking and promotion/publication. It does not rerun the producer build or its test lifecycle.
- Promotion requires the merged same-repository PR, a successful trusted pre-merge build, the exact successful run attempt's unexpired bundle, and identical Git source trees. No eligible bundle or a mismatch means failure, not an automatic rebuild.
- Receipt, payload, native identity, immutable registry, signer, signature and fresh registry-consumer checks remain required. The consumer proof builds only the independent consumer, not the runtime or generator.

## Source identity

GitHub's tested PR merge commit and final main merge commit can have different SHAs with identical trees. The release tag, original signed receipt and adoption manifest retain the **actual tested commit SHA**. Main's tree must match exactly before promotion; no receipt or producer bytes are regenerated to disguise a rebuild.

Fork artifacts and builds completed after merge are not eligible. Producer artifacts retain the existing one-day retention; merge only while the successful candidate is available. Failed or expired promotion never permits replacement of published coordinates.

Both coordinates remain an exact same-version pair:

- `io.github.gmcnicol:saas-kernel:0.3.3`
- `io.github.gmcnicol:saas-kernel-taxi-generator:0.3.3`

No downstream dependency pin or Application deployment changes automatically. Published 0.3.2 bytes and historical performance/platform evidence remain unchanged.
